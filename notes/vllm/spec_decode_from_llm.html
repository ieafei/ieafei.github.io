从 LLM 应用角度理解 Speculative Decoding

以 draft → verify → reject 三阶段为主线，理解投机解码的工作原理、接受率数学推导，以及提升接受率的实践技巧

🎯背景与动机

大模型推理的瓶颈在于 自回归解码：每次 forward pass 只能生成 1 个 token，GPU 的计算能力大量浪费在 memory-bandwidth 上，而非真正的矩阵运算。

Speculative Decoding（投机解码） 的核心思路：用一个小而快的 draft model 先"猜"出 K 个候选 token，再让大 target model 在 1 次 forward 中同时验证全部 K 个 token，最终通过拒绝采样保证输出分布与纯 target model 完全等价。

关键保证：在数学上，经过正确的拒绝采样后，最终输出的 token 分布与只用 target model 自回归采样完全一致（分布等价，非近似）。

⚠️ 实际注意：开启 spec decode 后，生成结果与纯 target model 推理不完全一致。这是因为 draft model 与 target model 即使在相同 input ids 下推测出的下一个 token 也可能不同，而这些不同的 draft token 在 case 1 和 case 2 中仍然可能被 accept，从而影响后续采样的随机数序列。

🗺️总体流程：Draft → Verify → Reject

1
Draft
Draft model 自回归生成 K 个候选 token（快速，小模型）
→
2
Verify
Target model 1 次 forward 同时计算所有 K+1 个位置的概率分布
→

逐位比较 p(x) 与 q(x)，决定 accept / reject，保证分布等价

示例：K = 4 个 draft token

Prompt The sky is → Draft blue and very clear → Target 验证 blue ✓ and ✓ very ✗ bright*

* 第 3 个 draft token 被拒绝后，target model 从残差分布重新采样得到 correction token，后续 draft token 全部丢弃。

✏️阶段 1：Draft Model 生成 Draft Tokens

Draft model 是一个与 target model 同架构但参数量更小的模型（例如 Llama-7B 给 Llama-70B 做草稿）。它以自回归方式连续生成 K 个 token，每次 forward 只需极少的计算量。

输入 t₁ t₂ … tₙ → Draft ×K d₁ d₂ … dₖ

输出：K 个 draft token d₁…dₖ，以及 draft model 在每个位置的概率分布 q(x)（用于后续拒绝采样）。

参数典型值说明
K（draft 数量）4 ~ 6甜点区间；太小加速不足，太大后段 token 常被拒绝
Draft model 大小Target 的 1/10 ~ 1/5越小越快，但接受率越低
Draft model 类型同家族小模型Llama-7B → Llama-70B 效果远好于跨架构

🔍阶段 2：Target Model 1 次 Forward 验证所有 Draft Token

将 prompt + K 个 draft token 拼接成长度为 n + K 的序列，送入 target model 做 1 次 forward pass，同时得到 K+1 个位置的 logits（对应 K 个验证位置 + 1 个新位置）。

t₁ t₂ … tₙ d₁ d₂ … dₖ → Target 1× forward p(1) p(2) … p(K+1)

✅ 加速来源：原本需要 K 次 forward（自回归），现在只需 1 次 forward（并行验证），节省了 K-1 次大模型推理开销。

Target model 输出每个位置的概率分布 p(x)，其中 p(x, dₓ) 表示 target model 在位置 x 对 draft token dₓ 赋予的概率。

🎲阶段 3：拒绝采样（Reject Sampling）

符号定义

符号说明
p(x) = target model 在位置 x 的概率分布向量（vocab_size 维） q(x) = draft model 在位置 x 的概率分布向量（vocab_size 维） p(x, dt) = target model 对 draft token dt 在位置 x 的概率：p(x)[dt] q(x, dt) = draft model 对 draft token dt 在位置 x 的概率：q(x)[dt]

逐位决策流程

对每个 draft token dₓ（从左到右），执行以下决策：

比较 p(x, dt) 与 q(x, dt)
↓
Case 1：p ≥ q
直接 Accept ✓
target 比 draft 更偏好此 token
Case 2：p < q
以概率 p(x,dt)/q(x,dt) 接受
r = random(0,1)
↓
r < p/q
Accept ✓
r ≥ p/q
Reject ✗
从残差分布重采样
↓
Correction Token *
后续所有 draft token 丢弃

Correction Token 的计算

当 draft token 被拒绝时，需要从 残差分布 中重新采样，以保证最终输出分布等价于纯 target model：

# 残差分布：clamp 后归一化 residual = torch.clamp(p_dist - q_dist, min=0) correction = torch.multinomial(residual, num_samples=1)

直觉：p - q 表示 target model 相对于 draft model "多出来"的概率质量。clamp 到 0 以上后归一化，得到的分布只包含 target model 比 draft model 更偏好的 token，从而修正 draft model 的偏差。

概率对比可视化（示例）

假设位置 x=2，draft token 为 "very"，vocab 中部分 token 的概率如下：

p("very")
0.25
q("very")
0.55

p < q → Case 2，以概率 0.25/0.55 ≈ 0.45 接受。若被拒绝，从 clamp(p - q, 0) 归一化后重采样，得到 target model 更偏好的 token（如 "bright"）。

📐完整示例走查

以 K=4 为例，展示一次完整的 spec decode 步骤结果：

位置 Draft token p(x, dt) q(x, dt) Case 结果
x=1 blue 0.70 0.50 Case 1（p ≥ q） ✅ Accept
x=2 and 0.60 0.40 Case 1（p ≥ q） ✅ Accept
x=3 very 0.25 0.55 Case 2，r=0.60 ≥ 0.45 ❌ Reject → 采样 bright
x=4 clear — — — 🗑️ 丢弃（前序已拒绝）
最终输出 blue and bright （本步共接受 3 个 token）

✅ 本步 1 次 target forward 产出了 3 个 token（2 accept + 1 correction），相比纯自回归节省了 2 次 target forward。

🚀提高 Spec Decode 接受率的方法

接受率（acceptance rate）越高，每步产出的有效 token 越多，加速比越大。以下是四个关键维度：

01
同模型家族
用 Llama-7B 给 Llama-70B 做草稿，远好于混用不同架构。相同训练数据和目标使两者分布更接近。
02
任务可预测性
代码补全、翻译、结构化输出的接受率通常高于创作类写作或开放式聊天。
03
更低温度
采样更确定时，草稿模型与目标模型更可能一致，接受率显著提升。
04
合适的 K 值
K=4~6 通常是甜点区间。太小（K=2）加速不足；太大（K=10）后段 token 常被拒绝，反而浪费。

📝总结

Speculative Decoding 的核心价值在于：

  1. 分布等价：拒绝采样在数学上保证输出分布与纯 target model 一致（理论上）
  2. 加速来源：用 K 次小模型 forward 换取 1 次大模型 forward，节省 K-1 次大模型推理
  3. 接受率决定收益：接受率越高，每步产出 token 越多，加速比越大
  4. 实际不完全一致：draft model 的存在改变了随机数序列，导致与纯 target 推理结果有差异

✅ 关键公式：Correction token 来自 clamp(p_dist - q_dist, min=0) 归一化后的残差分布，这是保证分布等价的数学核心。
